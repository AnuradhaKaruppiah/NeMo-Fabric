This page summarizes NVIDIA NeMo Fabric 0.6.0. [GitHub Releases](https://github.com/NVIDIA/NeMo-Fabric/releases) remain the source of truth for complete release history and tag-specific notes.

## Current Release

NeMo Fabric 0.6.0 adds explicit environment lifecycle APIs and an OpenShell provider, runtime health checks, resource snapshots and invocation statistics, and selected software execution evidence. It adds Kiro and AWS Strands adapters through a shared Agent Client Protocol (ACP) runner, supports Harbor 0.24, and updates Relay-enabled integrations for NeMo Relay 0.11.

## Upgrade Notes

<Warning>

The `nemo-fabric[relay]` extra and the Deep Agents, mini-SWE-agent, and NOOA Relay integrations now require `nemo-relay>=0.11,<0.12`. Keep Hermes Agent on `nemo-relay>=0.10,<0.11` in its separate environment. Claude, Codex, and Pi support Relay CLI releases `>=0.9,<0.12`; the Pi extension must match the CLI release. Remote HTTP model trust requires Relay CLI 0.11.

</Warning>

Relay 0.11 requires HTTPS for remote model endpoints by default, including private-network addresses. For a trusted, credential-free HTTP model endpoint, set `harness.settings.insecure_http_model_hosts` to its exact hostname or IP address. Requests and responses travel unencrypted, and Relay removes credential headers before forwarding. Remote telemetry collectors also require HTTPS by default. Restart existing runtimes after changing Relay versions. Refer to [Install NeMo Relay](../getting-started/install.mdx#install-nemo-relay) for migration details and collector trust configuration. Observability configuration remains version 4.

Two collection features are enabled by default:

- Invocation resource statistics collect before/after readings. Set `FabricConfig.system_stats=None` to disable them; periodic sampling remains opt-in. The independent final `resource_snapshot` is not disabled by this setting.
- Selected software evidence is enabled through `FabricConfig.provenance`. Set `ProvenanceConfig(enabled=False)` before initialization to skip collection. Old saved results can omit the optional `execution` field.

Upgrade the runtime, adapters, adapter contract, and the new `nemo-fabric-evidence` package together. The runtime and adapter contract use the same version-matched evidence package; the SDK does not depend on the southbound adapter contract.

Rust callers constructing `FabricConfig` or `RunResult` with complete struct literals must account for the added collection controls and optional result fields. Prefer defaults where available. The Harbor extra now selects `harbor>=0.24,<0.25`.

## Release Highlights

### Environment Lifecycle and OpenShell Execution

The SDK separates sandbox ownership from agent runtime ownership with `prepare_environment()`, `attach_environment()`, `start_runtime_in()`, and `release_environment()`. A NeMo Fabric-owned environment is deleted on release; a caller-owned environment is detached without deleting its resource.

The optional [OpenShell provider](https://github.com/NVIDIA/NeMo-Fabric/tree/main/environment-providers/openshell) routes ordinary SDK operations into a task image through `fabric-agent-ctl`. One sandbox can host multiple runtimes, and stopping one runtime leaves the others usable. Provider readiness is checked before runtime startup, sandbox IDs prevent accidental attachment to same-name replacements, and declared artifacts are copied back to host paths with bounded, verified transfers.

The maintained [Hermes Code Review](https://github.com/NVIDIA/NeMo-Fabric/tree/main/examples/code_review_agent) and [custom LangGraph agent](https://github.com/NVIDIA/NeMo-Fabric/tree/main/examples/langgraph_custom_agent) examples exercise this SDK path, with optional Relay support. Refer to the [sandbox command bridge](../sdk/python.mdx#sandbox-command-bridge) for lifecycle and cleanup behavior.

### Runtime Health Checks

Use `Fabric.check()` to check an agent runtime, an OpenShell runtime server, or a prepared or attached OpenClaw Gateway service. Checks return typed observations with `passed`, `failed`, `unknown`, or `unsupported` outcomes under one timeout budget. Supported `live`, `active`, and `ready` levels depend on the adapter's native evidence; a busy runtime can still be healthy.

OpenShell routes server and runtime checks through `fabric-agent-ctl check`, independently of an in-flight invocation. Refer to [Health Checks](../sdk/health-checks.mdx) for the supported levels and evidence for each adapter.

### Resource Snapshots and Invocation Statistics

Use runtime resource snapshots and `RunResult.system_stats` to inspect adapter process-tree CPU and memory, invocation duration, and visible Linux cgroup limits and conditions. Optional bounded sampling captures transient demand between the default before/after readings. Results distinguish unsupported, unavailable, and uncollected observations.

The code-review and Harbor examples expose collection controls and sampled artifacts. Refer to [Resource Usage and Stats](../sdk/system-stats.mdx) for metric groups, sampling limits, and interpretation.

### Selected Software Execution Evidence

`RunResult.execution` records selected software versions and existing infrastructure reports with their participants, original capture times, sources, and coverage. SDK and adapter snapshots are collected at initialization and reused; the compiled core reports its own executing version. Caller-owned reports can be supplied through `FabricConfig.provenance.reports`.

Evidence survives the OpenShell host/guest path and OpenClaw service reuse. Harbor can supply application evidence or disable collection through `fabric_provenance`. Missing or malformed optional reports become explicit coverage gaps without replacing the invocation outcome. Refer to [Selected Software Evidence](../sdk/python.mdx#selected-software-evidence).

### Kiro and AWS Strands Adapters

The shared ACP runner supports [Kiro CLI V3](../integrations/harness/kiro.mdx) and [AWS Strands](../integrations/harness/strands.mdx). Each runtime owns a harness process and persistent conversation, with supported MCP configuration, invocation-local usage, and deadline cleanup. Install and authenticate the corresponding harness separately; consult each guide for supported configuration and limits.

### Usage, Telemetry, and Harness Reliability

- OpenCode usage follows verified invocation coverage, Cline uses complete NVIDIA request totals, and Kilo Code usage includes all invocation steps. Harbor no longer backfills normalized usage from ATIF trajectories.
- Claude reports per-invocation cost and cache token usage. Deep Agents supports configured reasoning effort; Claude exposes effort controls and `max_buffer_size`; Codex accepts normalized `max` and `ultra` effort values.
- Kilo Code supports long-running prompts beyond Node's default fetch timeout. OpenClaw invocation timeouts respect the NeMo Fabric deadline, and OpenHands failures expose the underlying SDK error.
- Relay OpenTelemetry export supports file sinks. mini-SWE-agent trajectories retain tool results, and Relay gateway readiness waits are bounded.
- Dependency updates address release-scan findings and align supported harness versions. Refer to the release's lockfiles for exact versions.

## Current Limitations

- Initial OpenShell provider support is qualified on Linux with matched OpenShell 0.1.2 components. The command bridge returns buffered results and rejects streaming requests. Service hosting remains a local SDK capability. Artifact collection is bounded and does not copy an entire workspace.
- Health levels are adapter-specific observations, not interchangeable guarantees of model availability or prompt acceptance. Unsupported levels remain explicit.
- Resource statistics do not measure remote model-server or tool-server resources. Shared cgroup measurements cannot be attributed exclusively to one invocation, and GPU usage is not collected by this resource API.
- Software execution evidence is a selected inventory, not a full dependency inventory, reproducibility guarantee, or attestation. Input and configuration capture remain outside this contract.
- Kiro and Strands do not advertise Relay telemetry or native NeMo Fabric streaming. Cancellation and cold resume remain outside the supported adapter lifecycle contract.
- The adapter catalog contains metadata snapshots; it does not provide provider-backed executable registries or an automated adapter conformance suite.
